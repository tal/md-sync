# Review fixes: config persistence, recovery naming, logs and unused APIs

- Removing the committed repo config used to clear only the running daemon's layer. Its old settings survived in the state file and returned after an invalid replacement and restart. Repo-config loading now shares one policy across startup and reload; persistence shares one helper across the daemon and one-off runs. A removed file is saved as `{ blob: "none", layer: {} }`, so absence stays a known empty layer rather than reviving old ignore patterns or becoming unknown.
- Legacy rescue recovery had its own conflict-copy namer, which missed the fix for a parent reserved as a file by HEAD or the index but absent on disk. It tried 100,000 impossible names and stopped recovery. Rescue restoration now uses the worktree move's namer, placing the saved file under a conflict-copy name for the blocking parent.
- Six filesystem diagnostic sites used the `git` event with fabricated subprocess fields. They now emit `worktree operation failed` or `worktree operation skipped`, with `action`, `path`/`paths`, and `error` or `reason`. The `git` event remains reserved for commands executed by the Git wrapper. Log consumers filtering those filesystem diagnostics should use the new names.
- Removed production exports `rescueSave`, its save-only option types, `addLiteral`, `advanceBranch`, and `versionBytes`. The legacy rescue producer lives only in `test/helpers/legacy-rescue.ts` as `saveLegacyRescue`, to build old-version recovery fixtures. Legacy manifest readers and restoration remain supported. Tests of unused commit helpers were removed; the temporary-index isolation test still exercises the active tree/index helpers.
- Regression coverage checks config removal observed through reload, startup and a one-off flush, followed by an invalid replacement and restart; legacy recovery under a tracked parent absent from disk; and ownership of `git` log events. The README describes persisted removal and the new diagnostics.
- The full integration run exposed a polling-watcher test whose "old" file could share a clock millisecond with an ignore reload. The test now separates those steps before checking that only newly created files are reported; watcher behavior is unchanged.
