# Pin Bun 1.4.2 (latest stable), container image included

## What changed

| File | Change |
|---|---|
| `.bun-version` | `1.3.13` → `1.4.2`, the latest stable release (`bun-v1.4.2`, published 2026-09-05; checked with `gh api repos/oven-sh/bun/releases/latest` and `npm view bun version`). |
| `Dockerfile` | `FROM oven/bun:slim` (floating) → `ARG BUN_VERSION=1.4.2` + `FROM oven/bun:${BUN_VERSION}-slim`. The `1.4.2-slim` tag exists on Docker Hub (pushed 2026-09-05). |
| `.github/workflows/ci.yml` | The container job builds with `--build-arg BUN_VERSION="$(cat .bun-version)"`. |
| `test/unit/scripts.test.ts` | New test: the Dockerfile's `BUN_VERSION` default must equal `.bun-version`, and `FROM` must use it. |
| `.github/workflows/release.yml` | Header comment: on 1.4.2 each x64 asset and its `-baseline` sibling are the same runtime. |
| `docs/ARCHITECTURE.md` | §16.3 Dockerfile snippet, §16.4 container and release rows, "Pinned toolchain" paragraph, §20 D36. |

`package.json` `engines.bun` stays `>=1.3.0`: the code was verified on 1.3.13 through 2026-10-08. CI no longer runs 1.3.x, so raise it if a 1.4-only API is ever used.

## What was learned or corrected

- **The container image was the one unpinned piece.** CI and the release binaries already read `.bun-version`, but the Dockerfile floated on `oven/bun:slim`, so the image could run a different Bun from the one CI verified. Now one file decides all three, and a unit test catches drift.
- **On 1.4.2, the AVX2 and baseline x64 runtimes are byte-identical, glibc and musl alike.** I downloaded the four `bun-v1.4.2` zips and compared the `bun` binaries inside: `linux-x64` = `linux-x64-baseline` (sha256 `a83d2637…`), and `linux-x64-musl` = `linux-x64-musl-baseline` (`16b72935…`). The zips differ by exactly 36 bytes, which is just the longer name in four zip headers. So every x64 release asset now runs on any x64 CPU. The README table and the release matrix keep both assets and the "needs AVX2" wording: it's safe advice, and it stays right if a later Bun splits them again.
- **1.4.2 is the release that broke CI before (EINVAL instead of ENOENT for a long missing socket path on macOS).** That was fixed in code (`sendFlush` lstat-checks the path first), and every test run on 2026-10-09 already ran on 1.4.2, the Bun installed on this machine.
